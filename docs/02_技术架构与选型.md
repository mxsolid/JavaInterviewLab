# 02 技术架构与选型

## 1. 总体架构

```text
React 19 + TypeScript
        │ HTTP/JSON
        ▼
Spring Boot 3.5.x + Java 21
        │
        ├── Content：分类 / 专题 / 题库
        ├── Study：进度 / 答题 / 错题 / 笔记 / 复习
        ├── Scenario：场景 / Case / Solution
        └── System：配置 / Seed / 健康检查
        │
        ▼
PostgreSQL 16+
```

V0.1～V0.3 不要求 Redis。

## 2. 为什么项目先使用 Spring Boot 3.5.x

虽然更新的大版本已经存在，但本项目目标是：
- 快速做出稳定学习工具；
- 让学习者能看懂代码；
- 避免第三方生态兼容成本干扰学习。

因此先使用成熟稳定的 3.5.x，Java 使用 21。
题库中再专门增加：
- Spring Boot 3 与 4 的差异；
- Spring Framework 6 与 7；
- Jakarta 迁移；
- Java 17 / 21 / 25 特性。

## 3. 为什么用 MyBatis

- 更贴近国内 Java 后端实际岗位；
- SQL 显式可见，便于复习索引和 SQL；
- 比复杂 ORM 更容易解释执行过程；
- CRUD 规模不大，不需要过度封装。

原则：
- 简单 CRUD 可使用 Mapper；
- 复杂 SQL 放 XML；
- SQL 不拼接用户输入；
- DTO 与数据库对象分离。

## 4. 为什么 PostgreSQL 是事实源

学习数据最怕“看起来保存了，实际丢失”。

所以：
- PostgreSQL 保存所有关键状态；
- Redis 以后只能加速；
- 前端 localStorage 只能保存 UI 偏好，不能保存唯一学习进度。

## 5. 前端架构

建议：
- React 19
- TypeScript
- Vite 8
- Ant Design
- TanStack Query
- React Router
- Markdown Renderer
- Web Speech API

目录：

```text
frontend/src/
├─ app/
├─ api/
├─ components/
├─ features/
│  ├─ dashboard/
│  ├─ content/
│  ├─ study/
│  └─ scenario/
├─ theme/
├─ types/
└─ utils/
```

## 6. 配置原则

全部通过环境变量 / application profile：
- PostgreSQL URL
- 用户名
- 密码
- API Base URL
- 日志级别

禁止把端口、密码、路径散落写死在代码中。

## 7. Redis 预留方式

不在前三版创建强依赖，只预留：
- `cache` 包边界；
- application 配置段；
- 后续热点题缓存接口。

不得为了“技术栈丰富”提前增加 Redis。
