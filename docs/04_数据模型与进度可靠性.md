# 04 数据模型与进度可靠性

## 1. 设计目标

题库内容会持续增加，因此数据库必须：
- 能扩展；
- 不因新增字段频繁推翻模型；
- 系统题和用户题共存；
- 进度可靠；
- 保留历史。

## 4. 多层答案

`question_answer.answer_type`：
- QUICK_30S
- STANDARD
- DEEP

这样以后可增加：
- SOURCE_LEVEL
- REVIEW_CARD

而不用改 question 主表。

## 5. 关系模型

`content_relation`：

```text
source_type
source_id
relation_type
target_type
target_id
sort_order
```

可表示：
- 题目 → 题目
- 题目 → 场景
- 场景 → 设计模式
- 场景 → 源码专题
- 题目 → AI 专题

这是后续知识图谱、关联推荐的基础。

## 6. 学习进度“不能丢”的实现

### question_attempt：只追加
每次用户练习均 INSERT，不 UPDATE 历史记录。

记录：
- 是否查看答案
- 自评分
- 用时
- 是否标记不会
- 答题文本（可选）
- created_at

### study_progress：当前快照
保存：
- stage
- mastery_level
- attempt_count
- wrong_count
- last_studied_at
- next_review_at
- updated_at
- version

### 一个事务完成
“提交一次练习”必须：
1. INSERT question_attempt
2. UPSERT study_progress
3. 必要时 UPSERT review_task

任何一步失败整体回滚。

## 7. 笔记可靠性

- `note.version` 乐观锁；
- 前端 800～1200ms debounce 自动保存；
- 页面明显显示：保存中 / 已保存 / 保存失败；
- 保存失败保留本地编辑内容，不清空输入框。

## 8. 数据备份预留

V0.2 后可增加：
- JSON 导出；
- `pg_dump` PowerShell 脚本；
- 导入前校验版本。

Redis 不参与备份关键路径。
