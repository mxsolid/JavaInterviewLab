# 05 题库内容模型与扩展规范

## 1. 目标

后续可以持续补充：
- 高频题
- 大厂公开面经题
- 场景题
- 源码题
- 设计模式题
- AI / Agent 题
- 新 JDK / Spring 版本题

程序无需因题库扩充而改代码。

## 2. 题目内容标准

★★★★★ 题目建议完整包含：

```text
标题
一句话理解
通俗讲解
为什么这样设计
30秒回答
标准回答
深入回答
代码案例
得分点
常见错误
高频追问
业务场景
相关知识
版本说明
参考来源
```

★★★★ 可减少深入源码。
★★★ 以理解和使用为主。

## 3. 必须回答“为什么”

例如不要只写：

> HashMap 默认负载因子 0.75。

还要说明：
- 它在时间和空间之间做了什么平衡；
- 更大 / 更小会怎样；
- 面试中不应把“0.75 是数学最优值”当成绝对结论。

每个核心答案优先包含：
- 原因；
- 权衡；
- 反例；
- 使用边界。

## 4. 初始化题库分批策略

### Seed Pack 01：生存必会
约 50～80 个核心专题：
- Java 基础
- 集合
- 并发
- JVM
- Spring
- 数据库
- Redis 基础概念
- 网络
- 设计模式

### Seed Pack 02：高频场景
- 缓存穿透 / 击穿 / 雪崩
- 缓存一致性
- 分布式锁
- MQ 可靠性
- 幂等
- 秒杀
- 订单超时
- 支付重复
- 库存超卖
- 线上排查

### Seed Pack 03：扩展面试
- JDK 11 / 17 / 21 / 25
- Spring Boot 3 / 4
- 微服务
- Docker / K8s 基础
- AI / LLM / RAG / Agent / MCP
- Spring AI / LangChain4j

## 5. 设计模式题必须加入

优先：
- 单例
- 工厂
- 策略
- 模板方法
- 责任链
- 代理
- 观察者
- 装饰器
- 适配器
- 建造者

每种模式不只背定义，至少要有：
- Java 示例；
- Spring / JDK 中的真实例子；
- 业务例子；
- 什么时候不要使用。

例如“支付渠道选择”适合策略模式；
“统一业务步骤但部分步骤可替换”适合模板方法；
“审批 / 过滤器链”适合责任链。

## 6. 场景内容规范

一个 Scenario 下允许 N 个 Case。

一个 Case 下允许 N 个 Solution。

`scenario_case_solution` 保存：
- 推荐等级
- 是否最终防线
- 适用条件
- 优点
- 缺点
- 风险
- 排序

这样才能做方案矩阵，而不是写死表格。

## 7. 来源与版权

来源只用于：
- 证明题目方向；
- 保存公开面经 / 官方文档 / 开源项目引用；
- 后续核查更新时间。

不要大段复制开源仓库文章。
应自行整理解释，并记录 source URL、license、retrieved_at。

可研究的方向：
- JavaGuide：知识结构、面试范围
- advanced-java：分布式 / 高并发场景
- mall / mall-swarm：电商订单和业务建模
- Hello Algo / Algorithm Visualizer：可视化教学思路
- interview-guide：后续 AI 模拟面试架构

## 8. Seed 格式

Seed 使用 JSON，后端导入服务完成校验和幂等。

禁止直接写 1000 行 INSERT 维护题库内容。
