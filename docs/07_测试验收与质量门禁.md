# 07 测试验收与质量门禁

## 1. 后端

每个 Service 至少覆盖：
- 正常流程；
- 参数非法；
- 资源不存在；
- 唯一约束；
- 状态不允许；
- 事务回滚。

关键事务必须集成测试：
- question_attempt + study_progress；
- note optimistic lock；
- scenario case / solution 映射。

## 2. API

统一返回：

```json
{
  "success": true,
  "code": "OK",
  "message": "成功",
  "data": {},
  "traceId": "..."
}
```

错误码使用 Enum，不散落字符串。

## 3. 前端

至少验证：
- Loading；
- Empty；
- Error；
- 表单校验；
- 保存成功；
- 保存失败；
- 刷新后数据仍在；
- 查询参数保留；
- 返回列表时尽量保留筛选条件。

## 4. 数据可靠性专项

必须人工验证：
1. 学一道题；
2. 写笔记；
3. 提交练习；
4. 标错题；
5. 关闭前后端；
6. 重启；
7. 确认所有状态仍存在。

## 5. 质量门禁

禁止标记 DONE：
- 编译失败；
- migration 无法从空库执行；
- 中文乱码；
- console 大量异常；
- 前端存在 mock 假数据替代真实 API；
- Controller 直接访问 Mapper；
- 关键业务没有测试；
- PROGRESS 未更新。
