# 09 日志、注释、枚举与编码规范

## 1. 中文注释

正确：

```java
// 先写入答题历史，再更新当前学习快照。
// 两者必须在同一事务中，避免出现“进度更新了但答题历史丢失”的不一致状态。
```

不推荐：

```java
// 更新进度
progress.update();
```

## 2. Javadoc

以下类型必须有中文 Javadoc：
- Controller 和公开接口；
- Service 和 public 业务方法；
- Mapper 及非显而易见方法；
- Entity / Row；
- 枚举和每个枚举值；
- 复杂 DTO、事务、乐观锁和状态迁移。

重点说明：
- 业务职责；
- 事务边界；
- 关键参数；
- 可能抛出的业务异常。

不要给每个 getter/setter 写废话注释。

## 3. 枚举

所有业务枚举必须包含中文类注释、每个枚举值的中文注释和 `description` 字段。枚举名称保留给程序和协议，前端展示优先使用后端提供的 description。

## 4. Entity 与 Row

Entity 对应可写持久化记录，只在 Repository / Service 内部使用。复杂 JOIN 或聚合使用 `repository/model` 下的 Row record。Mapper 不返回 API Request / Response DTO，Service 负责转换。

## 5. 日志

使用参数化：

```java
log.info("题目创建成功, questionId={}, topicId={}", questionId, topicId);
```

不要：

```java
log.info("题目创建成功：" + questionId);
```

## 6. 错误日志

异常只在统一边界记录一次，避免 Controller、Service 重复打印同一个堆栈。

## 7. TraceId

后端统一请求过滤器生成 / 透传 traceId：
- 响应体返回；
- 日志 MDC 包含；
- 方便定位前后端问题。

## 8. UTF-8

所有：
- `.java`
- `.xml`
- `.yml`
- `.json`
- `.md`
- `.sql`
- `.tsx`
- `.ts`
- `.ps1`

均使用 UTF-8。

`.editorconfig` 应明确：
`charset = utf-8`

## 9. 时间

业务时间优先注入 `Clock`，不要在多个 Service 中散落 `Instant.now()` 或 `LocalDate.now()`。这样可以稳定测试自然日边界和未来开始时间等防御场景。
