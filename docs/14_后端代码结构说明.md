# 14 后端代码结构说明

后端按业务功能分包。`content` 放题库能力，`system/seed` 放导入能力，`common` 放响应、异常、日志和 OpenAPI 配置。

Controller 是 HTTP 门口：接收请求、校验 DTO、调用 Service、返回统一响应。它不直接调用 Mapper，因为 Controller 不应知道数据库细节。

DTO 是接口数据模型。它把请求和响应与数据库行隔开，例如 `QuestionCreateRequest` 不含 version，`QuestionUpdateRequest` 必须含 version。API Request / Response 优先使用 record。

Service 放业务规则与事务边界。题目保存时主表、答案、追问、标签必须一起成功或一起失败，因此 `@Transactional` 放在 Service，不放 Controller。

Mapper 是数据库访问接口。Mapper XML 保存 SQL、动态筛选和 JOIN；Java 接口只表达方法签名。这样 SQL 可读、可单独审查，也避免 Service 拼 SQL。

Repository 模型统一放在功能包的 `repository/model`：

```text
repository/
├─ XxxMapper.java
└─ model/
   ├─ XxxEntity.java
   └─ XxxRow.java
```

Entity 对应可写表记录，可使用 Lombok `@Data`；Row 是复杂 JOIN 的只读投影。Mapper 不返回 API Response DTO，也不接受包含页面子项的 Request DTO，防止接口变化反向污染 SQL 层。

Flyway 是数据库版本记录工具。启动时只执行尚未执行的 migration；已执行 migration 不可修改。`version` 是乐观锁版本号：更新 SQL 同时匹配 id 和 version，匹配不到就说明数据不存在或已被其他人更新。

学习路线目录在应用启动和 Seed 导入后显式同步；GET 查询只读。V5 删除 V4 中被 UNIQUE 与部分唯一索引覆盖的重复索引，避免无效写放大。
