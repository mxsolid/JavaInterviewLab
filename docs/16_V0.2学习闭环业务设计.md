# 16 V0.2 学习闭环业务设计

## B01 学习路线与每日计划

V0.2 的第一步是让用户选择一条真实存在的学习路线，而不是由前端临时拼出 Day N。

当前提供三条系统预设路线：

- 10 天突击：面试前快速覆盖核心题。
- 15 天推荐：在学习和复盘之间留出节奏。
- 30 天加强：增加输出练习和重复复盘。

路线内容存入 PostgreSQL。原因是路线属于产品内容，不是 UI 布局。题库更新后可以调整每天的知识分配；若写死在 React 中，每次调整都必须重新发布前端。

### B01 链路

输入：用户选择一条已启用的路线。

处理：后端锁定默认学习档案，取消旧路线的 active 状态，再激活新路线并写入新的 `started_at`。

状态变化：同一 profile 只有一条 active 的 `profile_plan`。旧选择保留为 inactive，后续可用于统计；当前路线以数据库为准。

输出：`current-plan` 返回自然时间进度，`today` 返回当前 Day 的专题或题目。

上游影响：B02 将写入答题历史，B03 才会计算“知识完成进度”。B01 的 `Day N` 只表示路线已进行的自然天数，不能表示题目已经学会。

### 系统路线初始化

内置路线定义放在后端资源 `study/study-plans.json`，通过 `StudyPlanBootstrapService` 幂等写入数据库。它不是前端 mock 数据。

路线项按题库的稳定业务键解析：专题使用 `topic.code`，题目使用 `question.external_key`。题库尚未导入时，路线和日计划仍会创建；现有 Seed 导入完成后会再次执行初始化，把可解析的关联项补齐。

这样可以兼顾两个事实：路线由数据库提供，同时初始题库也支持独立、幂等导入。
