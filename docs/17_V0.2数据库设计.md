# 17 V0.2 数据库设计

本文件记录已完成的 B01 表结构。答题历史、进度、复习、笔记和收藏表由后续任务分别补充。

## 表与职责

| 表 | 职责 |
|---|---|
| `profile` | V0.2 的本地学习档案。当前创建唯一默认档案，避免用户状态没有归属。 |
| `study_plan` | 一条系统学习路线，如 15 天推荐。 |
| `study_plan_day` | 路线中的 Day 1 至 Day N。 |
| `study_plan_item` | 某天关联的专题、题目；未来可关联场景。 |
| `profile_plan` | 学习档案选择过的路线，以及当前 active 路线。 |

`profile_plan` 的部分唯一索引 `uk_profile_plan_active` 保证一个 profile 同时只有一条 active 路线。切换路线时旧记录改为 inactive，而不是删除。

## 计划项关系

`study_plan_item` 使用 `target_type + target_id`：

- `TOPIC` 指向 `topic.id`。
- `QUESTION` 指向 `question.id`。
- `SCENARIO` 为 V0.3 预留。

这是一个受控的多目标关系。单列 `target_id` 无法同时建立多个外键，因此系统初始化只从受控 JSON 中解析已存在的专题和题目；普通 API 不提供计划项随意写入入口。

## 索引

| 索引 | 支持的查询 |
|---|---|
| `idx_study_plan_day_plan_day` | 查询一条路线的逐日计划、查询 Day N。 |
| `idx_study_plan_item_day_sort` | 查询某天的关联内容并保持固定顺序。 |
| `idx_profile_plan_active` | 读取默认用户的当前路线。 |

未为低频写入表添加额外索引，避免路线初始化和内容调整承担无用写入成本。
