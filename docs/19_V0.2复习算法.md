# 19 V0.2 复习算法

V0.2 使用固定间隔策略。它优先可解释，不使用 SM-2、FSRS 或后台定时推送。

| 最新状态 | 下一次复习 |
|---|---:|
| WRONG 或 UNKNOWN | 1 天后 |
| SEEN | 3 天后 |
| BASIC | 7 天后 |
| SOLID | 14 天后 |
| MASTERED | 30 天后 |

间隔定义在 `app.review.interval`。一次新的答题会在同一事务中：追加 `question_attempt`、更新 `study_progress`、完成旧 `PENDING` 任务、生成新的 `PENDING` 任务。

`review_task` 用部分唯一索引保证同一档案同一题最多一条待复习任务。已完成任务保留为历史。复习不是由定时任务“推送”出来的；首页和今日复习查询按 `due_at` 判断是否到期。

## 待处理复习语义

`GET /api/study/reviews/due` 与 Dashboard 的 `dueReviewCount` 使用同一范围：

```text
due_at < 明日 00:00 且 status = PENDING
```

因此：

- `due_at < 今日 00:00`：逾期，任务仍须显示，列表返回 `overdue=true`。
- `今日 00:00 <= due_at < 明日 00:00`：今日到期，列表返回 `overdue=false`。
- 明日及之后：不进入当前待处理集合。

这保证用户跨天未打开系统时，PENDING 任务不会因旧的日期下界而消失。
