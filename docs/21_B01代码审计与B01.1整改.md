# 21 B01 代码审计与 B01.1 整改

## 范围

B01.1 不新增学习闭环业务，只修正 B01 的质量和边界：

- content 与 study/plan 的中文 Javadoc；
- 业务枚举 `description`；
- Mapper 与 API DTO 解耦；
- 路线同步副作用、时间算法和重复索引；
- 学习路线页面默认详情、专题跳转和失败提示；
- 后端与前端回归验证。

## 已落实

- `AnswerType`、`Difficulty`、`FrequencyLevel`、`OriginType`、`QuestionType`、`ContentStatus` 均补齐中文说明和 `description`。
- 新增 `StudyPlanTargetType`，Bootstrap 不再使用 `TOPIC`、`QUESTION` 魔法字符串；未知目标类型在同步时抛配置错误。
- `content` 和 `study/plan` Mapper 仅使用 `repository/model` 的 Entity / Row，Service 负责 API DTO 映射。
- 应用启动和 Seed 导入后调用 `syncSystemPlans()`；`/api/study` 的 GET 链路不再写库。
- 同步单日路线项前先清理旧项，保证 JSON 删除后数据库不会继续返回该项；未解析目标记录 WARN，等待 Seed 导入后再次同步。
- 路线时间进度通过注入 `Clock` 计算，开始时间在未来时返回 Day 1，超过路线时长封顶。
- V5 删除 `idx_study_plan_day_plan_day` 与 `idx_profile_plan_active`，它们分别被 UNIQUE 和部分唯一索引覆盖。
- 前端优先展示用户选中路线，其次当前路线，最后首条系统路线；专题项跳转到对应题库筛选页。

## profile_plan 语义

`UNIQUE(profile_id, study_plan_id)` 使同一路线再次激活时更新原行并重置开始时间。因此该表记录“每条路线的最近一次选择状态”，不是逐次激活历史表。B01.1 不新增 activation_history。
